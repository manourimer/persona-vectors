# Synthetic Confound-Controlled Item Bank — Drafting Guidelines

Generated by [`scripts/build_synthetic_trait_bank.py`](../scripts/build_synthetic_trait_bank.py),
producing `data/processed/synthetic_trait_bank.{csv,parquet}`.

## Why this exists

The ETHICS-based analysis in this project (Stage 3 onward) is confounded by a
structural property of the benchmark: item *format* is almost collinear with
*trait* (deontology items are ~96% honesty, justice items are ~72% fairness,
etc. — see the README's Stage 2.3 discussion). Any apparent trait effect could
instead be a format effect, and this is repeatedly flagged as a limitation
throughout the paper rather than resolved.

This item bank is a small, purpose-built benchmark designed to remove that
confound entirely: one format, four traits, balanced ground-truth labels,
authored independently of the persona-vector construction pipeline. It
extends (and eventually replaces) the stalled `data/processed/
synthetic_moral_scenarios.csv` scaffold, which had no ground-truth label
column and was never wired into any extraction/projection script.

## Design rules followed while drafting

1. **Uniform format.** Every item is a single-sentence, first-person,
   past-tense declarative statement. No format varies across traits — this is
   the entire point: it removes the variable (format) that is entangled with
   trait throughout the ETHICS data.

2. **Matched pairs, not independent items.** Each trait has 20 pairs; within
   a pair, the "upheld" and "violated" items share the same context/setup and
   differ only in the trait-relevant action (e.g. *told the cashier about the
   extra change* vs. *kept the extra change without saying anything*). This
   holds topic, length, and register constant between labels, so a
   discrimination result can't be explained by a difference in vocabulary or
   subject matter between the two label groups — only by the trait-relevant
   content itself.

3. **Zero literal trait-label leakage.** No item uses the trait's own name or
   its close synonyms. Checked programmatically in the build script against
   the *exact* word list the project's own audit tool uses
   (`src/vectors/artifact_quality.py::_TRAIT_LABEL_WORDS`):
   - honesty: honest, honesty, truthful, truth, deceptive, lie, lies
   - harmlessness: harmless, harmlessness, safe, safety, harmful
   - fairness: fair, fairness, unfair, just, unjust, equal, equality
   - compassion: compassion, compassionate, empathy, empathetic

   This means the trait is inferable only from the action described, never
   from a keyword match — a projection score can't be explained by lexical
   overlap with the trait's own name.

4. **Single-trait isolation.** Each item engages exactly one trait. Scenarios
   that would entangle two traits at once (e.g. "lied to prevent harm," which
   mixes honesty and harmlessness) were deliberately avoided — the same
   cross-trait-confound risk the artifact-bank audit checks for in the
   contrastive construction prompts, applied here to the test items instead.

5. **Balanced labels.** `label = 1` means the trait was violated; `label = 0`
   means it was upheld — mirroring ETHICS' commonsense convention
   (`1 = wrong`). Exactly 20/20 per trait (40 items/trait, 160 total).

6. **Obvious but mundane.** Every item has one unambiguous correct answer a
   competent human rater would agree on instantly (matching the philosophy
   already stated in the old scaffold's notes), but grounded in everyday
   situations — work, family, strangers, money, shared information, pets,
   school — rather than extreme or dramatic scenarios, so the model isn't
   just pattern-matching to melodrama.

7. **Contextual diversity.** The 20 pairs per trait span varied settings
   (see the `annotation_notes` column for each pair's context label) so the
   vector is tested against varied surface content, not one repeated
   template.

8. **Independent of the construction pipeline.** No vocabulary or scenario
   type overlaps with `configs/trait_vector_artifacts.yaml`'s system prompts
   or elicitation questions (which are abstract "you are an assistant who…"
   persona instructions, structurally distinct from these concrete
   first-person scenarios). This preserves the bank as a genuine
   generalization test, not a rephrased contrast-validation check.

9. **Schema-compatible with the existing pipeline.** Columns mirror
   `data/processed/ethics_curated_mvp.parquet`
   (`item_id`, `scenario_text`, `primary_trait`, `source_split`,
   `keep_for_mvp`, plus `label`/`label_semantics` for validity analysis) so
   the file drops into `extract_ethics_activations.py` /
   `compute_ethics_projections.py` with minimal changes — just point
   `--item-bank` at the new file. `source_split` is set to the constant
   `"synthetic"` to keep it clearly distinguishable from `commonsense` /
   `deontology` / `justice` in any downstream group-by. An additional
   `pair_id` column (not present in the ETHICS schema) links each matched
   pair for paired-difference analysis.

## What this enables that ETHICS couldn't

- **Within-trait discrimination, format-controlled**: does the honesty
  vector actually separate honesty-upheld from honesty-violated sentences,
  in a format with zero cross-trait or genre confound?
- **Cross-trait diagonal dominance, format-controlled**: does the same
  27%-ish pooled diagonal dominance seen on ETHICS (concentrated almost
  entirely in justice-format items — see Table 7 in the paper) replicate,
  disappear, or strengthen once format stops varying with trait?
- **A second validity check** independent of ETHICS' ground-truth labels,
  since this bank's ground truth was authored directly against the trait
  definitions rather than inherited from a benchmark built for a different
  purpose (general ethical judgment, not moral-trait measurement).

## What this does not resolve

This bank is still a single author's judgment calls about what counts as
"obviously" upholding/violating a trait — it is a controlled instrument, not
a validated one (no independent human inter-rater check has been run on it,
unlike the ETHICS annotation pipeline's review stages). Treat results from it
as a robustness/converging-evidence check alongside the ETHICS findings, not
as a replacement for them.
